## 3. Storage Bucket & File Integrity Verification

### 3.1 Private Storage Bucket: `medical-records`
- **Access Level:** Strictly `PRIVATE` (No public URL reads permitted).
- **Access Policy:**
  - `INSERT`: Permitted only if authenticated user equals folder root: `auth.uid() = split_part(name, '/', 1)`.
  - `SELECT`: Restricted to time-limited signed URLs (`expiresIn: 300` seconds) generated by server actions after consent evaluation.
- **Document Tamper-Proofing:**
  - Every uploaded file buffer is hashed via `crypto.createHash('sha256')` on the server before storage dispatch.
  - The hash is stored in `medical_records.checksum` and verified on retrieval.

## 5. Live Staging Migration Application Runbook

To apply migrations against your live Supabase staging project:

1. **Option A: Supabase Dashboard SQL Editor (Recommended for Fast Verification)**
   - Open Supabase Project Dashboard ➡️ SQL Editor ➡️ New Query.
   - Paste contents of `supabase/migrations/20261107000000_zendoc_2_0_core_schema.sql` and run.
   - Paste contents of `supabase/migrations/20261108000000_zendoc_2_0_schema_corrections.sql` and run.

2. **Option B: Supabase CLI**
   ```bash
   npx supabase login
   npx supabase link --project-ref <your-project-id>
   npx supabase db push
   ```

3. **Verify Post-Execution:**
   ```sql
   SELECT table_name, rowsecurity 
   FROM information_schema.tables 
   JOIN pg_tables ON information_schema.tables.table_name = pg_tables.tablename 
   WHERE table_schema = 'public';
   ```
   Confirm all rows report `rowsecurity = true`.
